# 시연용 상품 데이터 작업 정리 (ETRI 패션 데이터셋)

시연 상품 데이터를 ETRI 패션 코디 데이터셋으로 채우기 위한 작업 내용을 정리한 문서다.
(작성 2026-11-24. 확인하지 못한 것은 "미확인"으로 적었다.)

## 1. 목표

- 체형(스트레이트 S / 웨이브 W / 내추럴 N)별 100개씩, **총 300개** 상품을 뽑는다.
- 상품마다 사진, 상품명, 가격, 상세 설명, 태그, 인기도, 신상 여부, 사이즈(S/M/L)를 갖춘다.
- Supabase `products`·`product_tags`에 넣어 홈·카테고리·검색·신상·베스트에서 보이게 한다.
- 이유: 기존 시연 상품 30개는 사진과 설명이 없어 알고리즘 효과가 잘 보이지 않는다. 네이버 쇼핑 검색 API는 신규 이용이 막혔고, 팀원이 직접 모으는 방식(`상품수집_가이드.md`)은 양이 부족하다.

## 2. 데이터 출처

- 이름: 한국전자통신연구원(ETRI) 「자율성장 인공지능 기술검증(PoC)을 위한 패션 코디 데이터셋」
- 주소: https://edr.etri.re.kr/data/b16e936b-1549-43a9-9490-c273b4bcf9a0 , https://www.data.go.kr/data/15129701/fileData.do
- DOI 10.22648/ETRI.2022.D.83 (2022-02-08 공개), 저작권은 ETRI에 있다.
- 받은 파일은 **저장소 밖**에 둔다: `D:\Dataset\Capstone\데이터\의류 데이터\` (`이미지/`, `mdata.wst.txt.2020.6.23`). 용량(약 305MB)과 이용 조건 때문에 **저장소에 올리지 않는다**.
- 활용 목적은 다운로드 신청 때 "과제 준비 / 졸업 과제 시연용 데이터로 활용"으로 적었다.

### 이용 조건 (반드시 지킬 것)
- 이용 시 ETRI 저작물임을 명시한다.
- 라이선스는 BY-NC-ND(출처표시·비영리·변경금지)로 보인다 (페이지에 배지 이미지만 있어 문구로는 확인하지 못했다. 공공데이터포털은 공공누리 4유형으로 같은 조건).
- 따라서: **비영리 시연에만 쓰고, 사진을 자르거나 편집하지 않는다.** 앱 스토어 공개·판매에 쓰지 않는다.
- 사진 속 상품을 판 쇼핑몰의 권리는 페이지에 나와 있지 않다(미확인). ETRI(edr@etri.re.kr)에 시연용 사용 문의를 하는 것을 권한다.

### 앱·발표에 넣을 출처 문구
> 상품 이미지와 속성 정보는 한국전자통신연구원(ETRI)의 '자율성장 인공지능 기술검증(PoC)을 위한 패션 코디 데이터셋'(DOI 10.22648/ETRI.2022.D.83)을 이용했어요. 졸업 과제 시연용이며 비영리로만 사용해요. 상품명·가격·설명은 시연을 위해 만든 정보로, 실제 판매 상품이 아니에요.

## 4. 태그 분석 결과 (2026-11-24, 현재 규칙·가중치 기준)

의류 2,473개의 F·M·E 문장을 `tagging.py`에 넣어 태그를 붙이고, 체형 100%인 사람 기준 `matching.match_item` 점수로 비교했다. 공백 정리 방식 두 가지(`_`만 제거 / 공백 전부 제거)로 돌렸고 결과가 조금 다르다.

| 항목 | 방식 1 | 방식 2 |
|---|---|---|
| 점수용 태그가 1개 이상 | 2,244 (90.7%) | 2,274 (92.0%) |
| 태그 2개 이상 | 1,552 | 1,540 |
| **태그 3개 이상** | **736 (29.8%)** | **700 (28.3%)** |
| 태그 4개 이상 | 244 | 233 |
| 정보 없음(제외) | 229 | 199 |

체형별로 가장 점수가 높은 아이템 수:

| | 내추럴 | 스트레이트 | 웨이브 | 동점 |
|---|---|---|---|---|
| 방식 1 | 1,061 | 627 | 226 | 330 |
| 방식 2 | 1,054 | 602 | 341 | 277 |

- 전체는 내추럴이 많고 웨이브가 적다(아우터가 특히 내추럴로 쏠림). 웨이브 후보는 최소 200~300개라 체형별 100개를 고르는 것은 가능하다.
- 종류별 태그 3개 이상: 상의 356~368 / 아우터 195~232 / 하의 95~104 / 원피스 41~45.
- 웨이브용 태그(`len:crop` 약 34개, `det:ruffle` 약 135개)가 적어서 웨이브 상품은 이 태그가 붙은 것 위주로 골라야 한다.
- 가중치는 임시값이고 동점이 많다. 시연에서 차이가 뚜렷하려면 한 체형에서만 점수가 높은 상품을 골라야 한다.
- 태그가 실제 옷·사진과 맞는지는 확인하지 못했다.

## 5. 작업 순서

1. 후보 거르기
   - 태그 3개 이상(종류에 따라 2개 이상) 우선, 정보 없음 제외
   - 체형별로 그 체형에서만 점수가 높은 상품 우선
2. 사진 거르기: 후보만 사진을 확인한다 (상품 전체가 보이는지, 얼굴·몸이 어색하게 잘렸는지, 흐리거나 너무 작은지, 종류와 사진이 맞는지). 최종은 사람이 훑어 확인한다.
3. 체형별 100개·종류별 균형 확정 → 총 300개
4. 상품명·가격(시연용)·브랜드(시연용)·S/M/L·인기도·신상 값 부여
5. 설명문 만들기 (아래 6장)
6. 사진을 앱이 읽을 수 있는 주소로 올리고 `main_image_url`에 넣기 (원본 그대로, 편집 금지)
7. Supabase 입력 (`seed_db.py`처럼 여러 번 실행해도 되게 만들기), 앱에서 확인

## 6. 설명문 만들기

- 메타데이터(F·M·C·E)만 근거로 쓴다. **메타데이터에 없는 내용은 쓰지 않는다.**
- 사용자에게 보이는 글이므로 "~해요" 체.
- 설명과 태그가 어긋나지 않게 한다 (추천 이유는 태그로 만들어진다).
- 검증: 설명에 나온 핵심 단어(칼라·핏·소재명 등)가 메타데이터에 있는지 스크립트로 대조하고, 30개쯤은 사람이 읽어 본다.
- 시연용 설명임을 출처 문구에 적는다.

## 7. 상품 한 개의 모양 (A·B 사이 약속)

| 필드 | 설명 |
|---|---|
| `product_id`, `product_name`, `clothing_type`, `brand`, `price` | 기본 정보 (가격이 0이면 앱에서 담기·구매가 막히므로 0 금지) |
| `main_image_url` | 사진 주소 |
| `description` | 상세 설명문 |
| `tags`, `seasons` | 태그, 계절 |
| `popularity` | 인기도 0~1 (베스트 순서에 쓰임) |
| `is_new` | 신상 여부 (아래 8장 미정) |
| `sizes` | S, M, L (DB `product_options`) |

현재 DB `products`에는 `description`·`main_image_url`·`popularity`가 있다. 서버는 `description`을 상품 응답에 실어 보낸다(11/25. 시연 상품 30개에는 가짜 설명을 넣었다. 앱 상세 화면 표시는 아직). 신상 구분용 컬럼이 있는지는 확인하지 못했다.

## 8. 역할 분담

| A: 데이터 선별 | B: 설명·화면 |
|---|---|
| 후보 정리, 사진 거르기 | 메타데이터 → 설명문 만드는 스크립트 (전체 후보 대상, 선별 전에 시작 가능) |
| 체형별 100개·종류 균형 확정 | 서버가 `description`·`is_new`를 내려주기, 앱 상세·신상·베스트 표시 |
| 상품명·가격·인기도·신상 값 부여 | 사진을 자르지 않고 보여 주는지 확인·수정, S/M/L 표시 |
| 사진 업로드, DB 입력 | 출처 문구를 공지사항과 상품 상세 하단에 넣기 |

- B는 시연 상품 30개에 가짜 설명을 넣어 먼저 개발하고, A가 300개를 확정하면 합쳐서 확인한다.
- A는 약속한 모양의 샘플 10개를 먼저 B에게 넘긴다.

## 9. 아직 정하지 않은 것

- **신상 기준**: 몇 %를 신상으로 할지, 신상 구분을 어디에 저장할지 (현재 앱의 신상 탭은 내장 상품 6개만 대상)
- **베스트 기준**: 인기도 상위 몇 %로 할지, 신상과 겹치지 않게 할지
- **"선호도"의 뜻**: 상품에 미리 넣는 값은 인기도뿐이고, 사용자 취향(`pref`)은 클릭·찜으로 서버가 자동 계산한다. 다른 뜻이면 정해야 한다.
- 사진 호스팅 위치 (Supabase 저장소 등)
- ETRI에 시연용 사용 문의 메일을 누가 보낼지
