# 홈 화면 ↔ 추천 알고리즘 연결 가이드 (프론트 담당 친구용)

> 앱은 안드로이드로 만들어요. **앱 담당은 `안드로이드_연결가이드.md`를 보세요.** 이 문서는 웹(JavaScript) 버전이고, 연습 화면(`/feed-demo`)이 이 방식으로 되어 있어요.

홈 화면에서 스크롤을 내리면 추천 알고리즘 순서대로 상품이 계속 나오게 하는 방법이에요.
연습용 완성본이 `recommend/templates/feed_demo.html`에 있어요. 저장소 맨 위에서 `python app.py`로 서버를 켜고 `http://127.0.0.1:5000/feed-demo`로 들어가 보면 동작을 확인할 수 있어요.

## 1. 상품 불러오기 (스크롤할 때마다)

```
GET /api/feed/scroll?user_id=아이디&S=0.6&W=0.3&N=0.1&page=0&size=10
```

| 값 | 뜻 |
|---|---|
| `user_id` | 사용자 구분용. 같은 아이디면 찜·구매 기록이 이어져요 |
| `S`, `W`, `N` | 체형 진단 결과 비율 (스트레이트·웨이브·내추럴). 첫 요청에만 보내면 되고, 다음부터는 저장된 값을 써요 |

설문 답을 바로 보내서 진단부터 하고 싶으면 처음 한 번만 이렇게 보내요. 그다음부터는 `user_id`만 보내면 저장된 체형을 써요.
```
POST /api/feed
{"user_id": "아이디", "answers": {"q1": 1, "q2": 3, "q3": 1, "q4": 2, "q5": 1, "q6": 1, "q7": 3},
 "measurements": {"height": 165, "shoulder_width": 31.5, "arm_length": 53.1, "upper_body_length": 47, "leg_length": 86.1}}
```
`measurements`는 없으면 빼도 돼요(설문만으로 진단). 답이 빠지면 400과 함께 어떤 문항이 빠졌는지 알려 줘요.
| `page` | 0부터 시작. 화면 바닥에 닿을 때마다 1씩 올려요 |
| `size` | 한 번에 받을 개수 (기본 10, 최대 50) |
| `season` | 생략하면 오늘 날짜 기준 계절 |

응답 예시:
```json
{
  "page": 0, "size": 10, "total": 24, "has_more": true,
  "body": {"primary": "S", "kind": "single", "ratio": {...}},
  "items": [
    {"product_id": "t01", "product_name": "칼라 셔츠", "clothing_type": "top", "score": 0.785,
     "reason": "칼라가 목선을 세워 주고, 몸에 맞는 핏이 라인을 정돈해 줘요.", ...}
  ]
}
```
- `items` 순서 그대로 화면에 붙이면 돼요. 순서가 곧 알고리즘 결과예요.
- `has_more`가 `false`면 더 부르지 않아요.
- `page=0`의 10개는 "오늘의 추천"과 같아요.

## 1-1. 홈 화면 토글 (골격 맞춤 추천 ON / OFF)

같은 주소에 `mode`만 바꿔서 보내면 돼요.

| 토글 | 보낼 값 | 추천 방식 | 체형 필요? |
|---|---|---|---|
| ON | `mode=body` (생략하면 이거) | 체형 적합도 60% + 취향 25% + 계절·인기 15% | 필요 |
| OFF | `mode=general` | 인기 50% + 자주 누른 스타일 30% + 계절 20% (일반 쇼핑몰 방식) | 없어도 됨 |

```
GET /api/feed/scroll?user_id=아이디&mode=general&page=0&size=10
```
- 토글을 바꾸면 목록을 비우고 `page=0`부터 다시 불러요.
- 찜·구매 기록은 두 모드가 같이 써요. OFF에서 누른 기록도 ON 추천에 반영되고, 반대도 마찬가지예요.
- 체형 진단을 안 한 사용자는 OFF만 볼 수 있어요. ON으로 바꾸면 400("체형 비율이 필요해요")이 오니, 그때 진단 화면으로 안내하면 돼요.
- 응답에 `"mode"`가 같이 와요.

## 2. 사용자 반응 보내기 (찜·구매 버튼)

```
POST /api/feed/event
{"user_id": "아이디", "product_id": "t01", "event": "like"}
```
- `event`: `click`(상품 누름), `like`(찜), `purchase`(구매), `return`(반품)
- 응답의 `need_rediagnosis`가 `true`면 `message`("체형을 다시 진단해 볼까요?")를 화면에 띄워 주세요.
- 반응을 보내면 다음 추천 순서가 바뀌어요. 바로 반영하고 싶으면 `page=0`부터 다시 불러오세요.

## 3. 무한 스크롤 최소 코드 (복사해서 쓰기)

```html
<label><input type="checkbox" id="toggle" checked> 골격 맞춤 추천</label>
<div id="list"></div>
<div id="sentinel">불러오는 중…</div>
<script>
  let page = 0, hasMore = true, loading = false;
  const ratio = "S=0.6&W=0.3&N=0.1";   // 체형 진단 결과로 바꾸기

  async function loadNext() {
    if (loading || !hasMore) return;
    loading = true;
    const mode = document.getElementById("toggle").checked ? "body" : "general";   // 토글 ON/OFF
    const res = await fetch(`/api/feed/scroll?user_id=me&${ratio}&mode=${mode}&page=${page}&size=10`);
    const data = await res.json();
    data.items.forEach(item => {
      const card = document.createElement("div");
      card.textContent = `${item.product_name} — ${item.reason}`;   // 디자인에 맞게 카드 꾸미기
      document.getElementById("list").appendChild(card);
    });
    page += 1; hasMore = data.has_more; loading = false;
  }

  // 토글을 바꾸면 처음부터 다시
  document.getElementById("toggle").addEventListener("change", () => {
    page = 0; hasMore = true; document.getElementById("list").innerHTML = ""; loadNext();
  });

  // 바닥 표시(sentinel)가 화면에 보이면 다음 10개를 불러옴
  new IntersectionObserver(e => { if (e[0].isIntersecting) loadNext(); })
    .observe(document.getElementById("sentinel"));
</script>
```

## 4. 알아 둘 점
- 지금 상품은 시연용 30개라서, 스크롤하면 금방 끝나요 (피해야 할 옷을 빼면 20여 개). 실제 상품 데이터가 들어오면 그대로 늘어나요.
- 상품 사진이 아직 없어요. 상품 데이터에 이미지 주소가 생기면 카드에 넣으면 돼요.
- 찜·구매 기록은 서버를 끄면 사라져요 (시연용).
