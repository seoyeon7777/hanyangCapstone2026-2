# 안드로이드 앱 ↔ 추천 서버 연결 가이드 (앱 담당용)

홈 화면에서 스크롤하면 추천 순서대로 상품이 계속 나오고, 토글로 **골격 맞춤 추천 ON / 일반 추천 OFF**를 바꾸는 데 필요한 내용이에요.
예시는 Kotlin + Retrofit(서버 통신 라이브러리) 기준이에요. 웹으로 된 동작 예시는 서버를 켜고 `/feed-demo`에서 볼 수 있어요.

## 1. 서버 켜기와 주소

저장소 맨 위 폴더에서:
```
pip install -r requirements.txt
python app.py
```
켜지면 접속 주소를 화면에 찍어 줘요.

| 앱을 돌리는 곳 | BASE_URL |
|---|---|
| 안드로이드 에뮬레이터 | `http://10.0.2.2:5000/` (에뮬레이터에서 `localhost`는 PC가 아니에요) |
| 실제 휴대폰 | `http://<서버 화면에 찍힌 PC IP>:5000/` — **PC와 같은 와이파이**여야 해요 |

접속이 안 되면: PC 방화벽에서 파이썬(포트 5000) 허용, 학교·공용 와이파이는 기기끼리 통신을 막는 경우가 있어서 휴대폰 핫스팟으로 PC를 연결해 보세요.

## 2. 앱 설정

**AndroidManifest.xml**
```xml
<uses-permission android:name="android.permission.INTERNET" />

<application
    android:usesCleartextTraffic="true"
    ... >
```
`usesCleartextTraffic`은 `http://`(암호화 안 된 주소)를 허용하는 설정이에요. 안드로이드 9부터 기본으로 막혀 있어서 개발 중에는 켜야 해요. 서버를 `https`로 올리면 끄면 돼요.

**build.gradle (Module: app)**
```gradle
implementation "com.squareup.retrofit2:retrofit:2.11.0"
implementation "com.squareup.retrofit2:converter-gson:2.11.0"
```

## 3. 주고받는 데이터

### 3-1. 홈 피드 (무한 스크롤) — `GET /api/feed/scroll`

| 파라미터 | 뜻 |
|---|---|
| `user_id` | 사용자 구분 (로그인 아이디 등). 같은 값이면 찜·구매 기록이 이어져요 |
| `mode` | **토글** — `body`(ON, 골격 맞춤) / `general`(OFF, 일반 추천) |
| `page` | 0부터. 화면 바닥에 닿을 때마다 1씩 올려요 |
| `size` | 한 번에 받을 개수 (기본 10, 최대 50) |
| `S`, `W`, `N` | 체형 비율. 처음 한 번만 보내면 서버가 기억해요 (설문으로 진단하면 안 보내도 됨, 3-2 참고) |
| `season` | 생략하면 오늘 날짜 기준 계절 |

응답 예시:
```json
{
  "mode": "body", "page": 0, "size": 10, "total": 30, "has_more": true,
  "body": {"primary": "S", "kind": "single", "ratio": {"S": 0.8, "W": 0.1, "N": 0.1}},
  "season": "fall",
  "items": [
    {"id": "b03", "name": "스트레이트 핏 데님", "category": "bottom", "score": 0.69,
     "reason": "곧게 떨어지는 라인이 몸의 직선을 깔끔하게 보여줘요. …", "tags": ["sil:IH", "mat:denim"], …}
  ]
}
```
- `items` 순서가 곧 추천 순서예요. 그대로 붙이면 돼요.
- `has_more`가 `false`면 더 부르지 않아요.
- 토글 OFF(`mode=general`)면 `body`가 `null`일 수 있어요 (진단 안 한 사용자).
- `category`: `top` 상의 / `bottom` 하의 / `outer` 아우터 / `dress` 원피스

### 3-2. 설문으로 진단 + 첫 화면 — `POST /api/feed`
```json
{"user_id": "u1", "mode": "body",
 "answers": {"q1": 1, "q2": 3, "q3": 1, "q4": 2, "q5": 1, "q6": 1, "q7": 3},
 "measurements": {"height": 165, "shoulder_width": 31.5, "arm_length": 53.1,
                  "upper_body_length": 47, "leg_length": 86.1}}
```
- 설문 7문항 답(1·2·3)을 보내면 서버가 체형을 진단하고 기억해요. `measurements`는 없으면 빼도 돼요.
- 응답의 `body.primary`(S 스트레이트 / W 웨이브 / N 내추럴)로 진단 결과를 보여 줄 수 있어요.
- 이후 스크롤은 `user_id`만 보내면 돼요.
- 응답 `sections`: "오늘의 추천", "상의", "하의", "아우터", "원피스", "추천 코디" (홈을 칸으로 나눠 보여 줄 때)

### 3-3. 사용자 반응 — `POST /api/feed/event`
```json
{"user_id": "u1", "item_id": "b03", "event": "like"}
```
- `event`: `click`(상품 누름) / `like`(찜) / `purchase`(구매) / `return`(반품)
- 응답: `{"pref": {...}, "need_rediagnosis": false, "message": ""}`
- `need_rediagnosis`가 `true`면 `message`("체형을 다시 진단해 볼까요?")를 띄워 주세요.
- 반응을 바로 순서에 반영하려면 `page=0`부터 다시 불러요.

### 3-4. 오류
모든 오류는 JSON이에요: `{"ok": false, "error": "체형 비율(S, W, N)이 필요해요 …"}` (HTTP 400·404·500)
- 진단 안 한 사용자가 토글 ON(`mode=body`)을 누르면 400 → 진단 화면으로 안내하면 돼요.

## 4. Kotlin 코드 예시

### 데이터 모양
```kotlin
data class FeedItem(
    val id: String,
    val name: String,
    val category: String,
    val score: Double,
    val reason: String
)

data class Body(val primary: String, val kind: String, val ratio: Map<String, Double>)

data class ScrollResponse(
    val mode: String,
    val page: Int,
    val total: Int,
    @SerializedName("has_more") val hasMore: Boolean,
    val body: Body?,
    val items: List<FeedItem>
)

data class EventRequest(
    @SerializedName("user_id") val userId: String,
    @SerializedName("item_id") val itemId: String,
    val event: String
)

data class EventResponse(
    @SerializedName("need_rediagnosis") val needRediagnosis: Boolean,
    val message: String
)
```

### 서버 주소 목록
```kotlin
interface FeedApi {
    @GET("api/feed/scroll")
    suspend fun scroll(
        @Query("user_id") userId: String,
        @Query("mode") mode: String,          // "body" = 토글 ON, "general" = 토글 OFF
        @Query("page") page: Int,
        @Query("size") size: Int = 10
    ): Response<ScrollResponse>

    @POST("api/feed/event")
    suspend fun event(@Body body: EventRequest): Response<EventResponse>
}

val api: FeedApi = Retrofit.Builder()
    .baseUrl("http://10.0.2.2:5000/")         // 실제 폰이면 PC IP
    .addConverterFactory(GsonConverterFactory.create())
    .build()
    .create(FeedApi::class.java)
```

### 무한 스크롤 + 토글 (Activity/Fragment 안)
```kotlin
private var page = 0
private var hasMore = true
private var loading = false
private val items = mutableListOf<FeedItem>()

private fun mode() = if (binding.algoSwitch.isChecked) "body" else "general"

private fun loadNext() {
    if (loading || !hasMore) return
    loading = true
    lifecycleScope.launch {
        try {
            val res = api.scroll(userId, mode(), page)
            if (res.isSuccessful) {
                val data = res.body()!!
                val start = items.size
                items.addAll(data.items)
                adapter.notifyItemRangeInserted(start, data.items.size)
                page += 1
                hasMore = data.hasMore
            } else if (res.code() == 400 && mode() == "body") {
                showDiagnosisScreen()          // 진단 안 한 사용자가 ON을 누른 경우
            }
        } catch (e: Exception) {
            showToast("서버에 연결할 수 없어요")
        } finally {
            loading = false
        }
    }
}

// 토글을 바꾸면 처음부터 다시
binding.algoSwitch.setOnCheckedChangeListener { _, _ ->
    page = 0; hasMore = true
    items.clear(); adapter.notifyDataSetChanged()
    loadNext()
}

// 바닥 근처에 오면 다음 묶음
binding.recyclerView.addOnScrollListener(object : RecyclerView.OnScrollListener() {
    override fun onScrolled(rv: RecyclerView, dx: Int, dy: Int) {
        val lm = rv.layoutManager as LinearLayoutManager
        if (lm.findLastVisibleItemPosition() >= items.size - 3) loadNext()
    }
})

loadNext()   // 첫 화면
```

### 찜 버튼

lifecycleScope.launch {

## 5. 알아 둘 점
- **상품 사진이 아직 없어요.** 상품 데이터에 이미지 주소 필드가 생기면 응답에 같이 실어 줄게요. 그 전까지는 카테고리별 기본 이미지를 쓰세요.
- **상품은 시연용 30개예요.** 피해야 할 옷도 빼지 않고 아래로 내리는 설정이라, 토글 ON/OFF 모두 30개가 나와요.
- **서버를 끄면 찜·구매 기록과 진단 결과가 사라져요** (지금은 메모리에만 저장). 시연 전에 서버를 껐다 켜지 않게 주의하세요.
- 서버 응답이 이 문서와 다르면 서연에게 알려 주세요. `recommend/test_api.py`가 위 모양을 자동으로 확인하고 있어요.
