# 가상 판매자 샘플 100개로 돌려 본 결과

## 무엇인가
- `samples/synthetic_sellers.json`: 가상 브랜드·가상 상품 100개. 실제 쇼핑몰의 상품이나 문구를 가져오지 않고, 쇼핑몰식 문체를 흉내 내 새로 썼다. 생성은 `python tools/make_synthetic.py`.
- 각 상품에 시나리오와 기대 결과(`expect`)가 붙어 있다. 기대 결과는 설계 문서(`판매자 등록 양식 설계.md`)의 규칙에서 내가 정했다.
- `python tools/run_synthetic.py`가 상품을 서버 API(`POST /api/items`)로 등록하고 기대 결과와 대조한 뒤, 체형 4종(S·W·N 단일, 혼합)으로 추천을 호출한다. 같은 대조가 `tests/test_synthetic.py`로 고정되어 있다.

## 구성 (11묶음, 100개)
| 묶음 | 개수 | 보는 것 |
|---|---:|---|
| A 양식을 모두 채움 | 12 | 모든 항목 입력 시 태그 생성 |
| B 필수만 입력, 글 보충 | 12 | 비운 선택 항목이 글에서 보충되는지 |
| C 설명 비움 | 5 | 상품명만으로도 보충되는지 |
| D 해당 없음 선택 유지 | 10 | "해당 없음"·"보통"을 고르면 글이 뒤집지 못하는지 |
| E 양식과 글 충돌 | 10 | 양식이 이기는지 |
| F 설명 노이즈 | 13 | 범례표, 반품 안내, 가죽패치, 제조일자, 코디 문장 등 오탐 방지 |
| G 혼용률 | 10 | 30% 경계, 3종 혼방, 확인 불가, 점수 없는 섬유 |
| H 글 보충 끔 | 3 | `text_fill=false` |
| I 잘못된 등록 | 14 | 필수 누락, 모순, 합계 오류, 중복 등이 거절되는지 |
| J 팀 입력(manual) | 6 | 같은 양식으로 입력한 외부 상품 |
| K 리뷰 일치도 | 5 | 계산과 형식 검증 |

## 결과
- 등록 시도 100개: 등록됨 85개, 거절됨 15개(잘못된 등록 14개 + 리뷰 형식 오류 1개). 기대 결과와 100/100 일치.
- 글 보충이 일어난 상품은 등록된 85개 중 26개.
- 첫 실행은 96/100이었다. 어긋난 4건은 모두 코드가 아니라 내가 쓴 기대값의 실수였고(상품명에 이미 "니트"·"스트레이트"·"와이드"가 있었음, 일치도 산수 오류), 기대값과 상품명을 고친 뒤 100/100이 되었다. 결과를 보고 기대값을 고쳤다는 점은 밝혀 둔다.

## 이 샘플로 발견해 고친 코드 문제
- 상의에 "와이드 핏 티셔츠"라고 쓰면 글에서 실루엣 태그(`sil:wide`)가 보충됐다. 실루엣 항목은 바지·치마·원피스에만 있는데 카테고리를 보지 않았기 때문이다. 이제 그 카테고리에 없는 항목·선택지의 태그는 보충하지 않는다(시나리오 F의 마지막 상품). 수정 전 동작으로 되돌려 확인했다.

## 한계
- 입력과 기대값을 모두 내가 만들었다. 규칙이 설계대로 동작하는지를 보여 줄 뿐, 실제 상품 설명에서 얼마나 잘 읽는지, 추천이 옳은지는 보여 주지 않는다.
- 설명 문체는 내가 쓴 것이라 실제 판매자들이 쓰는 표현의 다양성(오타, 영어 혼용, 이미지에만 있는 정보)을 대표하지 않는다.
- 태그 분포가 설계한 시나리오를 따르므로(예: 오탐 방지 시나리오가 많음) 실제 분포와 다르다.
