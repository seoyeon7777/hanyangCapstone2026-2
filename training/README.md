# training — 사진 기반 치수 추정 모델

사용자가 올린 정면·옆면 사진과 키·몸무게(·나이)로 몸 치수(길이·둘레)를 추정하는 모델을 만들기 위한 계획과 준비 코드다.
**정식 데이터로 학습하는 스크립트는 아직 없다.** 지금 있는 코드는 기준 오차를 재고, 입력이 끝까지 도는지 확인하는 것까지다.

> **최신 결과는 9장에 있다.** 0·2·4·5장은 사진을 받기 전(샘플 2명 기준) 상태로 쓴 글이라, "사진이 없다"는 말과 기준선 수치는 9장으로 대체된다.

데이터(사진·JSON·3D·CSV)에는 개인정보(이름, 출생년도 등)가 있다. **저장소에 올리지 않는다.** 가상환경도 저장소 밖에 둔다.

## 0. 한눈에 보기

- 목표: 길이·둘레 cm를 정확히 내는 것. 골격 진단은 설문이 맡고 사진은 cm만 맡는다(팀 결정).
- 서비스는 **여성만** 받는다. 비용은 **무조건 무료**여야 한다. 사진은 카메라 촬영이 아니라 **사용자가 찍어서 올리는 방식**이다.
- 가장 중요한 발견: **키·몸무게만으로도 둘레를 꽤 정확히 맞힌다**(허리 2.6, 가슴 2.4, 엉덩이 1.8cm). 지금 사진 방식은 이보다 훨씬 부정확하다.
- 그래서 모델은 **키·몸무게 기반 값을 기준선으로 두고, 사진으로 그 값을 보정**하는 구조로 만든다. 사진이 이상하면 기준선이 그대로 나온다.
- 막힌 곳: 학습용 **사진이 아직 없다**(정답 CSV와 라벨, 3D 일부만 받았다). 사진 zip을 사람 수십~백 명 분량이라도 받아야 학습·비교를 할 수 있다.

## 1. 목표와 제약

| 항목 | 내용 |
|---|---|
| 맞힐 치수 | 젖가슴둘레, 허리둘레, 엉덩이둘레, 어깨너비, 팔 길이, 다리 길이(샅높이). 팀이 쓰는 사이즈 경고용 |
| 입력 | 키(필수), 몸무게, 나이(선택), 정면 사진, 옆면 사진(오른쪽을 본 모습). 사진은 없을 수도 있다 |
| 평가 기준 | 줄자 실측 대비 평균 절대 오차(cm). 사이즈 일치율 같은 별도 지표는 쓰지 않는다 |
| 대상 | 여성만(남성 데이터는 학습에 보조로만 쓸 수 있다) |
| 비용 | 무료. 상용 API는 쓰지 않는다 |
| 사진 | 카메라 촬영 없음. 올린 사진을 가볍게 점검해서 경고만 보여 준다(`web/app.js`의 `photoWarnings`) |

사이즈 경고 로직은 옷 치수와 비교해서 나중에 언제든 고칠 수 있다. 모델은 **표준 정의의 몸 치수**만 정확히 내면 된다.

## 5. 모델 계획

### 5-1. 구조: 기준선 + 보정 (잔차 학습)
모델은 치수를 처음부터 맞히지 않는다.

```
예측 치수 = 키·몸무게(·나이) 기준선 + 사진 기반 보정값
```

- 기준선: 4-1의 일차식(릿지). 사진이 없거나 이상하면 보정을 0으로 두어 **적어도 기준선만큼은 나온다.**
- 보정값: 사진에서 뽑은 정보(폭·두께·길이)와 입력(키·몸무게·나이)을 받아 "기준선에서 얼마나 더하고 뺄지"를 예측한다. 보정 크기를 제한(예: ±3cm)하거나 정규화해서 사진 오류가 크게 반영되지 않게 한다.
- 표본이 사람 수(약 1,000명)로 제한되므로 모델은 작게 시작한다.

### 5-2. 입력과 전처리
- **키·몸무게·나이**: 표준화해서 넣는다. 나이와 사진은 **일부러 빼먹으며 학습**(입력 드롭아웃)해서 서비스에서 입력이 빠져도 동작하게 한다.
- **사진**: 정면(AI Hub 카메라 1~4번), 옆면(9~12번 우선, 25~28번은 좌우 반전으로 보조)을 쓴다. 후면은 5-5의 비교 실험으로 정한다.
- **윤곽은 서비스와 같은 분할 모델로 만든다.** 학습 사진도 MediaPipe 분할(웹과 같은 `selfie_segmenter`)로 윤곽을 만들어야 서비스 입력과 분포가 같다. AI Hub 폴리곤 라벨로 만든 깨끗한 윤곽으로만 학습하면 실제 입력과 달라진다. (안드로이드 앱은 윤곽에 ML Kit을 쓰므로, 앱에 붙일 때는 두 분할의 차이를 따로 확인해야 한다.)
- **사람 크기 정규화**: 관절로 사람 영역을 잘라서 몸 높이가 항상 같은 크기가 되게 맞춘다(웹의 `cropToPerson`과 같다). 거리 차이를 줄인다.
- 특징 입력(1단계): `features.py`가 만드는 폭·두께(가슴·허리·골반), 길이(어깨·팔·상체·다리), 두께÷너비 비율, 가슴·허리·골반 높이 비율, 윤곽 품질 신호(팔 제외 전후 폭 차이 등).
- CNN 입력(2단계, 필요하면): BMnet 방식으로 정면|옆면 윤곽을 하나의 이미지로 붙이고 키·몸무게를 상수 채널로 쌓아 MNASNet에 넣는다(`cnn_plumbing_test.py`로 입력이 끝까지 도는 것은 확인했다).

### 5-3. 학습 방법
1. **정답 정리**: 사람별 CSV에서 6개 항목을 뽑고 범위 밖 값을 뺀다. 허리 정의는 CSV의 "허리둘레"로 시작하고, "배꼽수준허리둘레"와의 차이를 같이 본다.
2. **사람 단위 분할**: 학습 80% / 검증 10% / 테스트 10%. **같은 사람의 사진이 두 곳에 걸치면 안 된다**(성별·연령대 비율 맞춤). 학습 사진은 사람마다 카메라·자세·옷 조합으로 여러 장을 만들되, 한 사람은 한 곳에만 둔다.
3. **옷 조건**: 옷은 측정복과 일상복을 모두 쓰되 옷 종류를 평가에서 따로 본다. 같은 몸에 다른 옷을 입힌 사진을 같은 정답으로 묶어서, 옷의 부피에 흔들리지 않게 한다.
4. **증강**: 윤곽 경계를 깎거나 부풀리기, 작은 구멍 만들기, 작은 기울기·이동·크기 변화, 키·몸무게에 작은 노이즈. 폰 사진에서 윤곽이 거칠어지는 상황을 흉내 낸다. (SMPL 기반 증강(ABS)은 구현 비용과 비상업 라이선스 때문에 미룬다.)
5. **손실**: 항목별로 표준화한 L1(평균 절대 오차 기준). 보정값에는 작은 규제를 둔다.
6. **모델**: ① 특징 기반(릿지, 그래디언트 부스팅) → ② 필요하면 CNN. 학습은 데스크탑(RTX 4060 Ti 16GB)에서 한다. 시간은 학습 자체가 몇 시간 안쪽, 사진 전처리가 사람 100명 기준 1시간 안팎, 1,000명이면 반나절~하루로 어림한다(추정이며 실제로 재 봐야 한다).
7. **남녀 데이터**: 서비스는 여성만이지만 데이터가 적어서, 남녀 1,000명으로 학습하고 성별을 입력에 넣되 **평가는 여성만으로** 하는 방법과 여성 500명만으로 학습하는 방법을 둘 다 본다.

### 5-4. 평가
- 항상 **기준선(키·몸무게·나이)과 같은 테스트 사람·같은 표**로 비교한다. 지표는 항목별 평균 절대 오차와 90퍼센타일 오차다.
- 보고 형식: 옷 종류별(측정복 / 일상복), 카메라별, 나이대별 오차를 따로 본다.
- 비교 대상 순서: ① 중앙값 → ② 키만 → ③ 키+몸무게+나이(기준선) → ④ 지금 규칙 기반 사진 방식 → ⑤ 학습 모델.
- **학습 곡선**: 학습 데이터 25%, 50%, 100%로 오차가 어떻게 줄어드는지 본다. 계속 줄면 데이터를 더 모으고, 50%와 100%가 비슷하면 다른 문제다.
- 마지막으로 **팀원 폰 사진 + 표준 줄자 실측**으로 환경 차이를 확인한다(스튜디오 결과가 폰에서도 이어지는지).

### 5-5. 비교 실험 (ablation)
| 실험 | 알아낼 것 |
|---|---|
| 사진 없음 vs 정면만 vs 정면+옆면 | 사진이 기준선에 더하는 정도와 옆면의 기여 |
| 정면+옆면 vs +후면 | 후면 사진을 사용자에게 요구할 가치가 있는가(사진이 3장이면 부담이 크다) |
| 측정복만 학습 vs 옷 6종 학습 | 옷 부피에 대한 강건성 |
| 특징 기반 vs CNN | 단순한 방법으로 충분한가 |
| 팔 제외 있음/없음 | 팔 제외가 학습 후에도 도움이 되는가 |
| 나이 입력 있음/없음 | 나이의 기여 |
| 남녀 학습 vs 여성만 | 데이터 양 vs 성별 일치 |

### 5-6. 서비스 연결 (무료 유지)
- 키·몸무게 기준선은 이미 웹에 있는 **일차식**이라 서버가 필요 없다.
- 보정 모델이 특징 기반이면 계수나 작은 트리를 JS로 옮기면 된다. CNN이면 ONNX로 변환해서 **브라우저에서 직접 실행**(onnxruntime-web)하면 서버 비용이 없고 사진이 기기 밖으로 나가지 않는다.
- 학습 때와 서비스의 **전처리가 같아야 한다**(윤곽 만들기, 자르기, 정규화). 규칙을 문서로 고정하고, 파이썬(`features.py`)과 웹(`web/app.js`)이 같은 숫자를 내는지 같은 사진으로 확인한다.

### 5-6-1. 사진이 이상할 때의 안전장치
- 폭·두께가 사이즈코리아 통계 범위(20대 여성 5~95분위: 가슴 폭 24.9~33.5, 두께 17.9~26.2, 골반 폭 31.3~38.0 등)를 크게 벗어나면 **사진 보정을 약하게 하거나 끄고** 경고를 보여 준다.
- 몸무게가 없으면 사진만으로는 둘레를 믿기 어렵다고 안내한다(몸무게가 둘레 정확도의 핵심).

### 5-7. 쓸지 말지 판단 기준
테스트 사람(여성)에서 기준선 대비 다음을 모두 만족하면 학습 모델을 서비스에 쓴다. 숫자는 임시 기준이며 팀이 정한다.
- 가슴·허리·엉덩이 중 둘 이상에서 평균 오차가 **10% 이상** 줄어든다.
- 나머지 항목(어깨·팔·다리)에서 기준선보다 나빠지지 않는다.
- 옷 종류별·카메라별 오차에서 기준선보다 심하게 나빠지는 곳이 없다.
- 팀원 폰 사진에서도 기준선보다 나빠지지 않는다.

**그렇지 않으면 학습 모델을 접고, 서비스는 키·몸무게 기준선을 쓰고 사진은 이상 감지(폭·두께 범위 점검)에만 쓴다.** 구조가 단순하고 설명하기 쉽다.

### 5-8. 위험과 대책
| 위험 | 대책 |
|---|---|
| 스튜디오 사진(위에서 내려다봄, 흰 배경)과 폰 사진의 차이 | 증강, 사람 크기 정규화, 팀원 폰 사진 검증. 개선이 안 보이면 5-7에 따라 접는다 |
| 사람 수가 적음(약 1,000명, 여성 500명) | 보정 구조(잔차 학습), 작은 모델, 남녀 학습 시험, 학습 곡선으로 데이터 필요량 판단 |
| 정답 정의 불일치(허리·어깨·팔) | 3장의 정의로 통일, 팀 실측도 같은 방법으로 |
| 옷 부피 | 몸에 붙는 옷 안내, 옷 종류별 평가, 안 되는 부분은 한계로 문서화 |
| 몸무게를 입력하지 않거나 틀림 | ±2kg에 강건함을 확인함. 입력이 없으면 사진 보정을 약하게 |
| 입력 오류가 섞인 정답 | 범위 필터, 학습에서 큰 오차 샘플 확인 |
| 윤곽 분할이 앱(ML Kit)과 웹(MediaPipe)에서 다름 | 서비스 위치(웹/앱)를 정한 뒤 해당 분할로 학습·검증 |
| 데이터 이용 조건 | AI Hub 신청 화면의 약관(학습 결과물의 활용 허용 취지)을 직접 확인. 결과물을 공개·상업화할 때 다시 확인 |

### 5-9. 단계별 할 일
1. **사진 확보**: AI Hub 이미지 zip 중 사람 수십~백 명 분량을 받는다(파일 목록에서 사람별·범위별 zip 크기 확인). 3D 8명으로 이상적인 윤곽 시험도 가능하다.
2. **전처리 스크립트**: 선택한 카메라·자세·옷 조합에서 정면·옆면 윤곽과 특징을 뽑아 저장(사람 번호별로). `features.py`를 확장한다.
3. **기준선·평가 스크립트**: 사람 단위 분할, 기준선 계산, 항목별 오차 표(5-4 형식).
4. **특징 기반 보정 학습**(5-1, 5-3) → 5-5의 ablation을 돌린다.
5. 부족하면 **CNN**(BMnet 방식)을 시도한다.
6. **팀원 폰 사진 검증**(표준 줄자 실측).
7. 5-7의 기준으로 **쓸지 말지 결정**하고, 쓰면 `web/`에 연결한다(5-6).

사진을 받아서 기준선과 사진 모델을 사람 단위로 나눠 평가했다. 오차는 모두 줄자 실측 대비 **평균 절대 오차(cm)** 이고, 학습에 쓰지 않은 사람으로 쟀다(5겹 교차검증 또는 다른 데이터셋 홀드아웃). 교차검증·카메라 비교 같은 실험 스크립트는 저장소에 넣지 않았다(임시 작업 폴더). **앱 모델을 만든 최종 학습 스크립트는 6장의 `train_photo_model.py` 등으로 저장소에 있다.**

### 9-1. 한눈에 보기

- **키·몸무게·나이 기준선**이 둘레 오차 약 2~3cm다. 둘레 정보의 대부분은 **몸무게**가 갖고 있다(키만 쓰면 평균을 쓰는 것과 같다).
- **정면+옆면 사진을 쓰는 CNN**은 일상복에서 기준선보다 12~15%(약 0.3cm), 몸에 붙는 옷에서 19~31% 낮았다. **헐렁한 옷 데이터(030)에서는 이득을 확인하지 못했다.**
- **현재 앱의 측정 로직**을 실제 앱(에뮬레이터)에서 돌려 보니 일상복에서 허리 약 17cm, 가슴 약 23cm 크게 나왔다. 앱 측정값을 그대로 쓰면 안 된다.
- 권장: **기준선 + 줄자 직접 입력을 기본**으로 하고, 사진 모델은 선택 기능으로 둔다. 앱에는 기준선 계산이 아직 없다(웹 `web/app.js`에만 있다).

### 9-3. 기준선 (사진 없이 키·몸무게·나이)

**정답 정의**: 사이즈 경고의 "가슴둘레"는 가장 나온 위치의 **젖가슴둘레**(사이즈코리아 표준 항목)로 정한다. 사이즈코리아의 "가슴둘레"는 겨드랑이 높이 기준이라 다른 값이다(030 CSV의 "가슴둘레"가 이쪽일 가능성이 높다. 사이즈코리아 8차로 만든 기준선을 030에 적용하면 +2cm 안팎 편향이 났다).

**학습 방법**
- 일차식(릿지), 입력 `[키 cm, 몸무게 kg, 나이]`. 값 = 절편 + 키×계수 + 몸무게×계수 + 나이×계수.
- 학습할 때 몸무게·키에 **평균이 0인 오차**(젖가슴·엉덩이·넙다리 SD 2.5, 허리 SD 1.5)를 섞는다. 사용자가 직접 입력한 값의 오차를 흉내 낸 것이다. 입력이 정확할 때 손해는 거의 없고(허리 3.30→3.40), 입력이 크게 틀릴 때 개선된다(151 가정 B에서 젖가슴 5.33→4.57, 허리 4.20→3.97, 엉덩이 3.51→3.13).
- 편향(예: 몸무게를 평균 2kg 적게 말함)까지 학습에 넣는 방식은 쓰지 않는다. 그 편향이 맞을 때만 좋고 정확한 입력에서는 나빠진다.
- 5~8차를 합친 것이 8차 하나보다 낫다(030 홀드아웃 가슴 3.30→3.00, 넙다리 3.07→2.59). 조사 연도를 입력에 넣으면 오히려 나빠진다.

**나잇대별 계수** (다른 나잇대에 영향이 없도록 따로 학습). 계수 순서는 `[절편, 키, 몸무게, 나이]`.

| 나잇대 | 항목 | 절편 | 키 | 몸무게 | 나이 |
|---|---|---|---|---|---|
| **19~79세** | 젖가슴 | 81.8554 | −0.2593 | 0.7417 | 0.1177 |
| | 허리 | 77.0192 | −0.3637 | 0.8587 | 0.2033 |
| | 엉덩이 | 62.6130 | 0.0028 | 0.5509 | −0.0367 |
| | 넙다리 | 41.7391 | −0.0476 | 0.4147 | −0.0716 |
| **13~18세** | 젖가슴 | 67.3808 | −0.1832 | 0.7401 | 0.2600 |
| | 허리 | 71.9442 | −0.2722 | 0.7709 | −0.0908 |
| | 엉덩이 | 52.8301 | 0.0027 | 0.5901 | 0.4017 |
| | 넙다리 | 38.8415 | −0.0738 | 0.4709 | 0.1378 |
| **10~12세** | 젖가슴 | 50.5908 | −0.0976 | 0.8331 | 0.1808 |
| | 허리 | 79.7070 | −0.3101 | 0.9671 | −0.9119 |
| | 엉덩이 | 37.7312 | 0.0546 | 0.7116 | 0.4419 |
| | 넙다리 | 34.6283 | −0.0670 | 0.5758 | −0.0140 |

- 나잇대를 하나의 모델로 합치지 않은 이유: 10~12세를 합치면 다른 나잇대 일부 칸의 오차가 늘었고(최대 +0.12cm), 13~18세를 성인과 합쳐도 151 성인 허리가 3.402→3.454로 조금 나빠졌다. 따로 두면 서로 영향이 없다.
- 그룹 내 교차검증 오차(젖가슴/허리/엉덩이/넙다리): 10~12세 1.95/2.11/1.61/1.59, 13~18세 2.41/2.31/1.75/1.67. 030 청소년(203명) 허리 2.95, 넙다리 1.99(성인 계수로는 3.20, 2.41).
- 경계에서 값이 계단처럼 바뀐다(18→19세는 1.6cm 이하, 12→13세는 큰 체격에서 최대 6cm). **10~12세 허리의 나이 계수(−0.91)는 이상하니 주의**한다. 10대·어린이 데이터는 2004~2015년 조사이고 8차에는 10대가 없다.
- **70대 이상은 계수를 따로 두지 않고 오차만 고지한다.** 70대 전용 계수는 넙다리(3.02→2.48)만 뚜렷하게 좋아졌고, 허리는 4.22로 그대로이며 030 노년 외부 검증에서는 허리가 오히려 나빠졌다. 학습 인원이 293명이고 80세 이상은 데이터가 없다.

**나잇대별 오차 범위** (정확한 키·몸무게 입력 기준, 평균 / 90%의 사람이 이 이내, cm)

| 나잇대 | 젖가슴 | 허리 | 엉덩이 | 넙다리 |
|---|---|---|---|---|
| 19~29세 | 2.4 / 4.9 | 2.6 / 5.4 | 1.8 / 3.8 | 1.7 / 3.5 |
| 30~49세 | 2.6 / 5.3 | 2.8 / 5.7 | 2.0 / 4.2 | 1.9 / 4.1 |
| 50~69세 | 2.7 / 5.6 | 2.9 / 6.1 | 2.0 / 4.3 | 2.3 / 4.8 |
| **70~79세** | 2.8 / 5.6 | **4.3 / 8.2** | 2.3 / 4.7 | **3.0 / 6.1** |

- 151 여성 478명 독립 검증(정확한 입력): 젖가슴 2.62, 허리 3.40, 엉덩이 1.91.
- 평균은 대표값일 뿐이다. 같은 키·몸무게·나이라도 허리가 유독 얇거나 허벅지가 두꺼운 사람은 4~5cm 이상 틀린다. 한 부위를 줄자로 알아도 다른 부위는 거의 좋아지지 않는다(엉덩이↔넙다리만 서로 연관). 줄자 입력은 부위마다 따로 받아야 효과가 있다.
- 평균 편향은 19~69세에서 ±0.8cm 이내다. 오차가 나이에 따라 커지는 것은 쏠림이 아니라 개인차 때문이다.

**입력(키·몸무게) 오차의 영향**: 위 오차는 조사원이 잰 값 기준이다. 앱 사용자가 직접 입력하면 커진다. **몸무게가 키보다 훨씬 중요하다**(키가 1~2cm 틀려도 거의 변화가 없지만, 몸무게 2kg 오차에서 허리 2.56→3.27~3.56). 입력 화면에서 최근에 잰 몸무게를 받도록 안내하는 것이 학습으로 줄이는 것보다 효과가 크다.

### 9-4. 사진 모델 (정면+옆면, 사진+키·몸무게·나이 입력)

151 여성 478명, 사람 단위 5겹 교차검증. 모델은 ResNet-18에 사진(사람 영역만 잘라 224×224)을 넣고 기준선 대비 잔차를 맞힌다. 일상복은 옷 5종 평균, 오차는 젖가슴 / 허리 / 엉덩이(cm).

| 모델 | 일상복 | 측정복(몸에 붙음) |
|---|---|---|
| 기준선 | 2.68 / 2.81 / 1.95 | 같음 |
| 정면+옆면, 사진별 예측 평균 | 2.45 / 2.48 / 1.70 | 2.09 / 2.23 / 1.39 |
| **정면+옆면을 한 모델에 함께 입력** | **2.36 / 2.45 / 1.66** | **2.05 / 2.27 / 1.34** |
| 정면만 | 2.73 / 2.64 / 1.69 | 2.47 / 2.39 / 1.40 |
| 옆면만 | 2.49 / 2.60 / 1.93 | 2.12 / 2.37 / 1.80 |
| 정면+옆면+후면 | 2.52 / 2.49 / 1.69 | 2.12 / 2.16 / 1.36 |

- **젖가슴은 옆면(몸의 두께), 엉덩이는 정면(몸의 폭)에서 이득이 난다.** 후면은 정면과 같은 폭 정보라 추가 이득이 없다. 사진은 정면+옆면 두 장이면 된다.
- 기준선 대비 개선은 일상복 12~15%(0.29~0.36cm), 측정복 19~31%다. 같은 입력에서 사진만 뺀 모델(사진에서 구한 사람 영역의 가로세로 비율·시점 정보는 포함)과 비교하면 일상복 개선은 5~13%다.
- **일상복도 학습에 넣어야 한다.** 측정복으로만 학습하면 일상복에서 기준선보다 나빠진다(2.76 / 3.00 / 2.05). 처음 보는 옷(그 옷을 학습에서 제외)에서도 같은 계열 일상복에서는 비슷하게 나온다.
- **저해상도·잡음 증강이 필수**다. 증강 없이 학습하면 저해상도(100px)+잡음 입력에서 엉덩이 이득이 사라진다(일상복 1.66→1.90, 측정복 1.34→2.03). 증강으로 학습하면 회복되고 깨끗한 사진에서도 성능이 유지된다.
- **헐렁한 옷(030, 609명)**: 윤곽 폭 + 선형 모델, CNN(ResNet-18, EfficientNet, ResNet-50) 모두 기준선(가슴 2.89, 허리 3.59, 넙다리 2.51)을 넘지 못했다. 원인(헐렁한 옷, 비스듬한 카메라, 옆면 사진 없음, 사람 수 중 무엇)은 분리하지 못했다.
- **가벼운 방식**(윤곽 폭으로 타원 둘레 계산 + 기준선 합침): 몸에 붙는 옷에서만 효과가 있고(+14~27%), 옷을 섞으면 기준선보다 나빠진다. 일상복에서 가슴 +9~10cm, 허리 +12~15cm, 엉덩이 +4.5~5cm 크게 나온다(옷의 두께).
- 이득은 크지 않다. 몸무게 입력에 오차가 있으면(−2±2kg) 입력 오차 하나가 만드는 악화(0.5~1cm)가 사진 이득(0.3cm)보다 클 수 있다.

### 9-5. 현재 앱의 측정 로직을 실제 앱에서 돌린 결과

앱을 빌드해 에뮬레이터(Android API 37.1)에 설치하고, 체형분석 → 카메라 화면의 "앨범에서 선택"으로 151 사진(10명 × 측정복/동복)을 넣어 "측정 위치 확인" 화면의 값을 읽었다. 측정선은 앱 기본 위치(가슴 29%, 허리 43%, 골반 52%)에서 조정하지 않았다. 20번 중 19번이 읽혔고, 키는 160으로 입력한 뒤 각 사람의 실제 키 비율로 환산했다.

| 옷 | 항목 | 실제 앱 오차 (편향) | 기준선 |
|---|---|---|---|
| 측정복(9명) | 젖가슴 / 허리 / 엉덩이 | 15.55 (+13.3) / 4.17 (+3.6) / 5.82 (−5.8) | 1.51 / 3.03 / 1.47 |
| 일상복(10명) | 젖가슴 / 허리 / 엉덩이 | 22.83 (+22.8) / 17.22 (+17.2) / 2.72 (+0.2) | 1.58 / 3.07 / 1.73 |

- 정면 폭의 양 끝점이 몸통이 아니라 **팔 위치**에 찍힌다(앱에 팔 제거가 없다). 가슴이 크게 나오는 주된 이유다. 일상복에서는 옷의 두께가 더해진다.
- 파이썬으로 같은 방식(팔 제거와 사람 영역 자르기 포함)을 재현했을 때(141명)는 일상복 가슴 약 9cm, 허리 약 17cm였다. 허리는 같았고 가슴은 실제 앱이 더 나빴다.
- 사람 10명, 옷 2종이라 평균은 대략적인 크기로만 본다.

### 9-7. 한계와 아직 안 한 것

- 151의 일상복 5종은 서로 비슷한 계열이고 같은 스튜디오(위에서 내려다보는 카메라)에서 찍었다. **폰으로 직접 찍은 사진, 후드·패딩·아주 헐렁한 옷, 앱의 각도·배경·조명**에서는 확인하지 못했다.
- **완전히 건드리지 않은 시험용 데이터는 없다.** 151과 030을 학습·검증에 모두 쓰고 설계(5~8차 선택, 오차 학습 강도)를 결과를 보며 정했다. 교차검증이라 같은 사람이 학습·시험에 섞이지는 않았지만 수치는 약간 낙관적일 수 있다.
- 오차는 조사원이 잰 키·몸무게 기준이다. 사용자 입력 편향 데이터가 없다. **팀원들의 실제 줄자 치수와 키·몸무게·나이를 모아 실제 사용 조건으로 확인**하는 것이 가장 좋다.
- 엉덩이둘레는 030에 정답이 없어 151에서만 검증했다. 넙다리둘레는 151 신체정보 CSV의 `넙다리둘레`에 정답이 있다(전원). 예전 학습 표에 옮겨 담지 않아서 사진 모델이 허벅지를 학습하지 않았던 것이고, `make_inputs.py`가 이제 함께 만든다.
- 030 1,440명 전체 사전학습, SMPL 합성 증강, 측정선 조정 효과, TFLite 변환·속도는 시험하지 않았다.
- 10~12세 허리 계수, 70대 이상, 경계(12→13세) 값은 불안정하다.
- 5~8차 3D 측정 시트와 1~4차 여성은 최종 학습에 쓰지 않았다(홀드아웃으로 쓸 수 있다).

### 9-8. 팀이 정할 것
- 나잇대 구성(10~12 / 13~18 / 19~79)을 앱에서 그대로 쓸지, 최소 나이를 몇 세로 할지.
- 사진 모델을 앱에 넣을지(9-7의 한계와 개선 폭 약 0.3cm를 감안). 5-7의 판단 기준(10% 이상 개선)을 일상복 기준으로 보면 가슴·허리·엉덩이 모두 약 12~15%라 넘지만, 폰 사진 검증이 남아 있다.
- 사이즈표의 가슴 정의(젖가슴둘레) 확정과 `SizeFitChecker` 여유값.
